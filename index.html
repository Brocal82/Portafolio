Ambulancias GoRuiz

Personal project 2025–2026 Archived

Role: Sole developer — product scope, architecture, backend, web, mobile, testing and CI

Multi-tenant operations platform for ambulance and patient-transport companies: shift planning, crews, vehicles, absences, documents, payslips and bonuses. Web panel for admins and superadmin, including worker views; Expo mobile app for field crews; Node.js / Express API with REST and WebSocket, backed by MongoDB.

Personal project, designed and built over many months. It reached an advanced functional development stage and was deliberately archived before production deployment — it has no customers or production users. Demo available on request.

  • Problem Small ambulance companies run rosters, crews and absences on spreadsheets and messaging apps.
  • Approach One API serving a web panel and a mobile app, with tenant isolation and role-based access.
  • Engineering 893 backend + 432 frontend tests, CI on every pull request, OpenAPI spec and documented technical debt.

Engineering

What GoRuiz demonstrates

Concrete, verifiable parts of the project — each one covered in more depth in the case study.

01

Multi-tenant by design

The company is resolved server-side from the database and enforced in the service layer, with a tenant-isolation test suite in CI.

02

Security-focused backend

JWT with token versioning, role-based access for four roles, TOTP MFA and step-up re-authentication, audit log and rate limiting.

03

Private file handling

Medical documents and PDFs are served only through an authenticated endpoint with ownership checks; the public path is limited to images.

04

Real-time updates

A WebSocket channel sends minimal refresh signals — no data over the socket; clients refetch through the authenticated API.

05

Tested against a real database

893 backend tests (Jest + Supertest on MongoDB) and 432 frontend tests (Vitest + Testing Library).

06

Documented and reproducible

OpenAPI 3 spec with 95 operations, CI with secret scanning, a recovery guide and a written log of known issues.
